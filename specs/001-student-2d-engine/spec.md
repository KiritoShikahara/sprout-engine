## 0. 概要と位置づけ

Sprout Engine は、専門学校 1 年生が授業と個人制作で使う 2D ゲームエンジンのサンプル実装である。**使う側は Unity 程度に簡単、作り（内部）は商業エンジン水準**を目標とする。

- 利用者（学生）は「エディタで配置 → C++ で振る舞いを書く → 再生して確認 → 配布用に書き出す」を、エンジン内部を知らずに完結できる。
- 内部は商業エンジンと同等の構成（アセットデータベース、GUID 参照、Prefab、物理、アニメーション、UI、入力アクション、ビルドパイプライン、プロファイラ）を持ち、上級学生・教員が設計の教材として読める。

### 0.1 アクター
| アクター | 説明 |
|---|---|
| 学生（Game Developer） | エディタとゲームコードを使ってゲームを作る。内部構造には触れない |
| 教員（Instructor） | 課題テンプレート・サンプルを配布し、学生の提出物をビルド・実行する |
| エンジン開発者（Engine Developer） | エンジン本体とエディタを保守・拡張する |
| プレイヤー（Player） | 書き出されたゲームを遊ぶ |

### 0.2 スコープ外
3D 描画、ネットワーク対戦、モバイル/コンソール/Web 書き出し、ビジュアルスクリプティング、C++ 以外のスクリプト言語、アセットストア、マルチユーザー同時編集。

## Clarifications

### Session 2026-10-21
- Q: 対象ゲーム → A: 2D 全般（スプライト・タイルマップ・当たり判定）
- Q: エディタ UI → A: ImGui-SFML（ドッキング式マルチパネル）
- Q: アーキテクチャ → A: Entity + Component。利用者が便利で使いやすいこと。利用者に内部構造をできるだけ触らせない
- Q: ビルド → A: CMake + vcpkg。Visual Studio 2022 と Visual Studio 2026 の両方でビルド可能
- Q: 命名規則 → A: constitution II で確定。テストは GoogleTest で必須
- Q: 規模 → A: 商業エンジン水準（下記モジュール全て）
- Q: 学生コードをエディタで実行する方式 → A: ゲームコードを「ゲームモジュール（DLL）」としてビルドし、エディタが読み込む。再ビルド時はエディタを再起動せずに再読み込みする
- Q: 内部構造の把握 → A: ER 図（ドメイン / ランタイム / エディタ）を仕様の付属文書として作成し、データ構造変更時は同時更新を必須とする

## User Scenarios & Testing *(mandatory)*

優先度は「授業で学生がゲームを完成させるために必要な順」。各ストーリーは単独で実演・検証可能。

### User Story 1 - コードだけで最初のゲームを動かす (Priority: P1)
学生はテンプレートから、30 行以内のコードで画像を表示しキーで動かせる。

**Why this priority**: エンジンの最小価値。エディタ無しでも授業 1 回目に使える。
**Independent Test**: サンプル `01_HelloSprout` で矢印キー移動、画像欠損時は代替画像とエラー表示。

**Acceptance Scenarios**:
1. **Given** テンプレート, **When** オブジェクトを作り画像を割り当てて実行, **Then** 画像が表示される
2. **Given** 移動処理を書いた振る舞い, **When** 入力アクション「Move」を操作, **Then** フレームレート非依存の速度で動く
3. **Given** 存在しない画像, **When** 実行, **Then** クラッシュせず代替画像と「何が・どこで・どうすれば」を示すメッセージ

---

### User Story 2 - プロジェクトを作り、エディタでシーンを組み立てる (Priority: P1)
学生はプロジェクトハブで新規プロジェクトを作り、エディタでオブジェクトを配置・編集・保存する。

**Why this priority**: 「エディタ付き」の中核。以降の全ストーリーの土台。
**Independent Test**: 新規プロジェクト作成 → 3 オブジェクト配置 → 保存 → エディタ再起動 → 同じ状態。

**Acceptance Scenarios**:
1. **Given** プロジェクトハブ, **When** テンプレート「2D Empty」で作成, **Then** フォルダ構成・設定・空シーンが生成されエディタが開く
2. **Given** シーン, **When** 移動/回転/拡大ギズモで操作, **Then** インスペクタ・シーンツリーと即時同期し、グリッドスナップが効く
3. **Given** 複数選択, **When** コピー＆ペースト / 複製 / 削除, **Then** 全対象に適用され 1 手で元に戻せる
4. **Given** 未保存の変更, **When** エディタを閉じる / シーンを切り替える, **Then** 保存確認が出る
5. **Given** 任意の編集, **When** Ctrl+Z / Ctrl+Y, **Then** 最低 200 手まで戻る/やり直せる

### User Story 3 - C++ で振る舞いを書き、エディタで再生して確かめる (Priority: P1)
学生は IDE で振る舞いを書き、ビルドするとエディタに反映され、再生ボタンで動作を確認できる。

**Why this priority**: 試行錯誤サイクル（書く→見る）の速さが学習効率を決める。
**Independent Test**: 振る舞いを追加しビルド → エディタ再起動なしでインスペクタに出る → 再生で動く → 停止で元に戻る。

**Acceptance Scenarios**:
1. **Given** エディタ起動中, **When** ゲームモジュールを再ビルド, **Then** エディタ再起動なしで再読み込みされ、シーン上の値は保持される
2. **Given** 振る舞いの公開プロパティ, **When** インスペクタで編集, **Then** 型に応じた入力欄（数値・範囲・色・アセット参照・オブジェクト参照・列挙）が出る
3. **Given** 再生中, **When** 停止, **Then** シーンは再生前に完全復元される
4. **Given** 再生中, **When** 一時停止 / 1 フレーム送り, **Then** 状態を観察できる
5. **Given** 振る舞い内で不正操作（破棄済み参照など）, **When** 実行, **Then** エディタは落ちず、コンソールに発生箇所付きでエラーが出て再生が一時停止する
6. **Given** ゲームコードがビルドエラー, **When** エディタ使用中, **Then** 前回成功したモジュールで作業を継続できる

### Edge Cases
- アセット・シーン・Prefab が欠損/破損 → 読み込みは継続、欠損参照は「Missing」として可視化、代替表示
- アセットをエディタ外で移動・改名 → GUID により参照は切れない。メタ情報の無いファイルは自動で登録
- 破棄済みオブジェクト/コンポーネント参照の使用 → 検出して無視しエラーログ（未定義動作にしない）
- 更新中のオブジェクト生成/破棄/コンポーネント追加 → フレーム内の定義された時点で安全に反映
- 長いフレーム（デバッガ停止・最小化） → 経過時間の上限で物理の暴走を防ぐ
- ゲームモジュールの再読み込み時に振る舞いのデータ構造が変わった → 一致するプロパティのみ引き継ぎ、消えたものは警告
- ゲームコード内のクラッシュ（例外・アクセス違反） → エディタは保護され、再生を停止しシーンを復元
- 新しい版のエンジンで古いファイル → 自動移行。より新しい版のファイル → 読み込み拒否と版の明示
- Prefab の循環参照 → 作成時に拒否
- 同名アセット/同名オブジェクト → 許容（識別は GUID / ID）
- 日本語を含むパス・ファイル名・テキスト → 全機能で正しく扱える
- 高 DPI・複数モニタ・ウィンドウ解像度変更 → エディタ UI とゲーム画面が崩れない
- エディタの異常終了 → 次回起動時に自動保存から復元を提案

## Requirements *(mandatory)*

番号帯: 001–099 コア / 100 シーン・オブジェクト / 150 スクリプト / 200 アセット / 250 描画 / 300 アニメーション / 350 物理 / 400 音 / 450 入力 / 500 UI / 550 シーン管理・永続化 / 600 ビルド / 650 診断 / 700 エディタ / 800 拡張 / 900 品質・非機能

### 1. コア（Core）
- **FR-001**: ゲームはウィンドウ設定（タイトル・解像度・フルスクリーン・垂直同期・目標フレームレート）を指定して起動できる
- **FR-002**: 時間は「可変更新」「固定更新（既定 50 Hz、設定可）」「後更新」を提供し、時間倍率（0 で一時停止）と時間倍率の影響を受けない実時間を取得できる
- **FR-003**: 1 フレームの最大経過時間を設定でき（既定 0.25 秒）、超過分は切り捨てる
- **FR-004**: 利用者のコードは例外を使わずに失敗を判定できる（成功/失敗 + 理由）
- **FR-005**: ログはレベル（Trace/Info/Warning/Error/Fatal）とカテゴリを持ち、コンソール・ファイル・エディタへ同時出力できる
- **FR-006**: 型付きイベント（発行/購読/購読解除）を提供し、購読側の破棄時に自動解除される
- **FR-007**: タイマー（遅延実行・繰り返し）とコルーチン（待機・次フレーム・条件待ち）を振る舞いから使え、所有者の破棄で自動停止する
- **FR-008**: 乱数（シード指定・範囲・確率・重み付き選択）を提供する
- **FR-009**: 数学ライブラリ（2D ベクトル・行列・矩形・円・色・角度・補間・イージング）を提供する
- **FR-010**: ジョブシステムで内部処理（アセット読み込み・パーティクル更新等）を並列化できる。利用者コードはメインスレッドのみで動作し、スレッドを意識しなくてよい

### 2. シーンとオブジェクト（Scene / GameObject）
- **FR-100**: シーン内でオブジェクトを生成・複製・破棄・名前/タグ/型で検索できる
- **FR-101**: オブジェクトは名前・有効状態・タグ（1 つ）・レイヤー（1 つ）・静的フラグを持つ
- **FR-102**: Transform は位置・回転・拡大と親子階層を持ち、ローカル/ワールド座標の相互変換ができる。親の無効化で子も無効
- **FR-103**: コンポーネントの追加・取得・削除・有効/無効化ができ、子/親方向の検索ができる
- **FR-104**: オブジェクト/コンポーネント参照は無効化を検出できる（破棄後は「無効」と判定できる）
- **FR-105**: 実行順序はコンポーネント型ごとに優先度で制御できる
- **FR-106**: 生成・破棄・コンポーネント追加削除は、更新中でも安全に要求でき、反映時点が仕様化されている（生成は次の更新前、破棄はフレーム末）
- **FR-107**: シーンをまたいで残るオブジェクトを指定できる
- **FR-108**: タグとレイヤーはプロジェクト設定で名前付きで定義する（レイヤー最大 32）

### 3. スクリプト（Behavior / Game Module）
- **FR-150**: 利用者は振る舞い型を定義し、ライフサイクル（生成時・有効化・開始・固定更新・更新・後更新・無効化・破棄）、衝突/トリガー、UI イベント、アニメーションイベントの処理を書ける
- **FR-151**: 振る舞いの公開プロパティ（整数・実数・真偽・文字列・色・ベクトル・列挙・アセット参照・オブジェクト参照・コンポーネント参照・配列）を宣言でき、範囲・ツールチップ・見出し・非表示の属性を付けられる
- **FR-152**: ゲームコードはゲームモジュールとしてビルドされ、エディタは再起動なしで再読み込みできる（シーン状態とプロパティ値を保持）
- **FR-153**: ゲームモジュール内の異常終了からエディタを保護し、再生を停止してシーンを復元する
- **FR-154**: 振る舞いの登録は 1 行で行え、エンジン内部型を一切記述せずに済む
- **FR-155**: 書き出し版ではゲームモジュールは実行ファイルに静的に組み込める

### 4. アセット（Asset Pipeline）
- **FR-200**: 全アセットは不変の GUID で識別され、ファイルの移動・改名で参照が切れない（メタ情報ファイルを併置）
- **FR-201**: 対応形式: 画像（PNG/JPG/BMP/TGA）、音声（WAV/OGG/FLAC/MP3）、フォント（TTF/OTF）、シーン、Prefab、マテリアル、シェーダ、アニメーションクリップ、アニメーター、タイルセット、ルールタイル、パーティクル、入力アクション、文字列テーブル、物理マテリアル
- **FR-202**: アセットごとにインポート設定（画像: フィルタ・ピクセル単位・ピボット・スプライト分割、音声: ストリーミング/事前読込）を持てる
- **FR-203**: エディタ外でのファイル変更を検知して自動再インポートし、使用中のアセットを即時更新する
- **FR-204**: 同一アセットは一度だけ読み込まれ、参照が無くなれば解放できる（参照カウント）
- **FR-205**: 非同期読み込みと進捗取得ができる
- **FR-206**: アセット間の依存関係（どれがどれを使っているか）を検索できる
- **FR-207**: 欠損アセットは代替アセット（画像: 紫黒チェッカー、音: 無音、フォント: 内蔵）で置き換え、警告する
- **FR-208**: スプライトアトラス（複数画像の自動パッキング）を作成できる

### 5. 描画（Rendering）
- **FR-250**: スプライト描画は描画レイヤー（名前付き）と順序値で前後関係を制御でき、同一テクスチャ/マテリアルは自動でまとめて描画される
- **FR-251**: スプライトは色・反転・9 スライス・タイル表示・マスクに対応する
- **FR-252**: カメラは複数配置でき、ビューポート・ズーム・背景色・描画対象レイヤー・描画先テクスチャを指定できる
- **FR-253**: カメラ補助として追従（遅延・先読み・不感帯）・移動範囲制限・画面揺れ・ピクセルパーフェクトを提供する
- **FR-254**: マテリアルとシェーダ（GLSL）で描画を差し替え、パラメータをエディタと振る舞いから設定できる
- **FR-255**: 2D ライト（点・スポット・全体）と影を落とす物体を設定できる
- **FR-256**: ポストエフェクト（ブルーム・ビネット・色調補正・ピクセル化）を重ねられる
- **FR-257**: パーティクル（発生形状・発生量・バースト・寿命・速度・重力・色/サイズ/回転の時間変化・テクスチャアニメ・ワールド/ローカル空間）を提供する
- **FR-258**: テキスト描画は TTF・日本語・リッチテキスト（色・太字・サイズ）・縁取り・影・折り返し・揃えに対応する
- **FR-259**: 線・ポリゴン・円などの図形描画コンポーネントを提供する
- **FR-260**: 画面外の物体は描画処理から除外する

### 6. アニメーション（Animation）
- **FR-300**: アニメーションクリップはスプライト切替と任意プロパティのキーフレーム（補間: 定数/線形/ベジェ）を持つ
- **FR-301**: アニメーターは状態・遷移・パラメータ（float/int/bool/trigger）・遷移条件・遷移時間・任意状態からの遷移・サブ状態機械を持つ
- **FR-302**: アニメーションイベントで振る舞いの処理を呼べる
- **FR-303**: トゥイーンは移動・回転・拡大・色・任意数値を、イージング・遅延・繰り返し・ヨーヨー・連結/並列で補間できる

### 7. 物理（Physics 2D）
- **FR-350**: 剛体は動的/運動学的/静的の種類、質量、重力倍率、減衰、回転固定、連続衝突検出、スリープを持つ
- **FR-351**: 当たり判定形状: 箱・円・カプセル・多角形・辺（連続線）・複合。オフセットとトリガー指定可
- **FR-352**: 物理マテリアル（摩擦・反発）を設定できる
- **FR-353**: 衝突レイヤー行列で衝突する組を設定できる
- **FR-354**: 衝突開始/継続/終了とトリガー開始/継続/終了を、接触点・法線・相手と共に通知する
- **FR-355**: レイキャスト・形状キャスト・点/範囲内検索をレイヤー指定で行える
- **FR-356**: ジョイント: 距離・回転（ヒンジ）・スライダー・バネ・固定・マウス追従
- **FR-357**: 物理は固定更新で決定的に進み、描画は補間されて滑らかに見える
- **FR-358**: 物理を使わない簡易な重なり判定も提供する

### 8. 音（Audio）
- **FR-400**: 音源は再生/停止/一時停止・音量・ピッチ・ループ・開始時再生・優先度を持つ
- **FR-401**: ミキサーグループ（階層）で音量・ミュートを一括制御できる
- **FR-402**: 位置付き音源は距離減衰（最小/最大距離）と左右定位を持ち、聞き手はカメラ等に付けられる
- **FR-403**: BGM のクロスフェード・フェードイン/アウトを提供する
- **FR-404**: 同時発音数の上限を持ち、超過時は優先度の低い音を止める

### 9. 入力（Input）
- **FR-450**: 入力アクション（ボタン型・1 軸・2 軸）をアクションマップ単位で定義し、キー・マウス・ゲームパッド（最大 4 台）を割り当てられる
- **FR-451**: 複合割り当て（WASD → 2 軸）、不感帯、感度、反転を設定できる
- **FR-452**: アクションの「押した瞬間/押している間/離した瞬間/値」を取得でき、イベントとしても受け取れる
- **FR-453**: 実行時にキー割り当てを変更（リバインド）・保存・復元できる
- **FR-454**: 生のキー/マウス/ゲームパッド状態、テキスト入力（IME 含む日本語）も取得できる
- **FR-455**: マウス座標を画面/ワールド座標で取得できる

### 10. UI（Game UI）
- **FR-500**: UI キャンバスは画面空間/ワールド空間と、基準解像度に対する拡大方式を持つ
- **FR-501**: UI 要素はアンカー・ピボット・余白で配置し、解像度変更に追従する
- **FR-502**: 要素: パネル・画像・テキスト・ボタン・トグル・スライダー・プログレスバー・入力欄・ドロップダウン・スクロール領域・マスク
- **FR-503**: 自動レイアウト: 縦・横・グリッド、内容に合わせたサイズ
- **FR-504**: マウス/タッチ/キーボード/ゲームパッドで操作でき、フォーカス移動の順序を指定できる
- **FR-505**: UI イベント（クリック・ホバー・値変更・フォーカス）を振る舞いで受け取れる
- **FR-506**: UI もアニメーション・トゥイーンの対象にできる

### 11. シーン管理・永続化（Scene Management / Persistence）
- **FR-550**: シーンを単独/追加で読み込み・解放でき、非同期読み込みと進捗取得ができる
- **FR-551**: シーン遷移にフェード等の演出を付けられる
- **FR-552**: Prefab はインスタンス化・入れ子・個別上書き（追加/削除/値変更）・上書きの適用/破棄・派生 Prefab を持つ
- **FR-553**: シーン/Prefab/アセットは人が読めるテキスト形式で保存し、版番号と自動移行を持つ
- **FR-554**: セーブデータは複数スロット・自動バックアップ・破損検出を持ち、任意の構造化データを保存できる
- **FR-555**: プレイヤー設定（音量・画面・キー設定・言語）を保存できる
- **FR-556**: 文字列テーブルで多言語化でき、UI テキストとフォントが言語に応じて切り替わる

### 12. ビルド・書き出し（Build）
- **FR-600**: ビルド設定（含めるシーンと順序・起動シーン・アイコン・製品名・版・ウィンドウ既定値・開発ビルド有無）を保存できる
- **FR-601**: 書き出しは使用アセットのみをパック化し、実行ファイルと共に単体で動くフォルダを生成する
- **FR-602**: エディタ無しのコマンドラインでビルド・書き出し・テスト実行ができる
- **FR-603**: 書き出し版は起動時に致命的エラーを利用者に分かる形で表示し、クラッシュ時はログを残す

### 13. 診断（Diagnostics）
- **FR-650**: プロファイラはフレーム時間・システム別時間・描画呼び出し数・オブジェクト数・メモリ・アセット数を記録し、任意区間の計測マーカーを利用者が置ける
- **FR-651**: デバッグ描画（線・矩形・円・文字・持続時間）を提供し、書き出し版では無効化される
- **FR-652**: 物理形状・カメラ範囲・UI 境界の可視化を切り替えられる
- **FR-653**: 開発用コンソールコマンド（登録・実行・補完）を提供する
- **FR-654**: 利用者向けエラーは日本語で「何が・どこで（オブジェクト/アセット/行）・どうすればよいか」を示す

### 14. エディタ（Editor）
- **FR-700**: プロジェクトハブ: 最近のプロジェクト一覧・新規作成（テンプレート選択）・開く・エンジン版の表示
- **FR-701**: ドッキング式パネル配置を保存/復元でき、既定レイアウトへ戻せる
- **FR-702**: シーンビュー: パン・ズーム・グリッド・スナップ・移動/回転/拡大/矩形ギズモ・複数選択（矩形選択）・ピボット/中心切替・ローカル/グローバル切替・選択強調
- **FR-703**: ゲームビュー: 解像度/アスペクト指定・拡大表示・統計表示
- **FR-704**: シーンツリー: 階層表示・ドラッグで親子変更/並べ替え・検索・有効/無効・ロック・表示切替・Prefab インスタンス表示
- **FR-705**: インスペクタ: 全コンポーネントとプロパティの編集、複数選択時の共通値編集、コンポーネントの追加（検索付き）/削除/並べ替え/コピー/リセット、Prefab 上書きの表示
- **FR-706**: アセットブラウザ: フォルダツリー・サムネイル・検索・フィルタ・作成・改名・移動・削除（ゴミ箱経由）・インポート設定・依存関係表示・外部エディタで開く
- **FR-707**: コンソール: レベル/カテゴリ絞り込み・集約・検索・発生元への移動・再生開始時の自動クリア設定
- **FR-708**: 専用エディタ: スプライトエディタ（切り出し・ピボット）、アニメーションエディタ（タイムライン・キーフレーム・カーブ）、アニメーターエディタ（ノードグラフ）、タイルパレット、パーティクルプレビュー、入力アクションエディタ、文字列テーブルエディタ、物理レイヤー行列
- **FR-709**: プロジェクト設定（タグ/レイヤー/描画レイヤー/物理/入力/音/時間/品質/ビルド）とエディタ設定（テーマ・ショートカット・フォントサイズ・自動保存間隔・言語 日/英）
- **FR-710**: 元に戻す/やり直す: 全編集操作が対象、最低 200 手、履歴一覧から任意時点へ移動、連続操作（ドラッグ）は 1 手に統合
- **FR-711**: 再生/一時停止/コマ送り/停止、再生中の値変更は停止時に破棄（指定した値のみ保持可能）
- **FR-712**: ゲームモジュールのビルド状態表示、IDE で開く、ビルド実行、コンパイルエラーの一覧表示
- **FR-713**: 自動保存とクラッシュ復旧
- **FR-714**: すべての操作はキーボードショートカットを割り当て可能で、既定値は一般的なエンジンに準ずる

### 15. 拡張（Extensibility）
- **FR-800**: カスタムインスペクタ・プロパティ描画・エディタウィンドウ・メニュー項目・アセット作成メニューを登録できる
- **FR-801**: 独自アセット型とインポーターを登録できる
- **FR-802**: 独自コンポーネントはエンジン標準と同等にシリアライズ・Undo・Prefab 上書きの対象になる

### 16. 品質・非機能（Quality）
- **FR-900**: 利用者向け公開 API と内部実装は分離され、利用者は内部実装へ依存するコードを書けない
- **FR-901**: 公開 API は例外を送出せず、未定義動作を起こさない（不正入力は検出してログ）
- **FR-902**: 自動テストが必須。公開 API の全機能・シリアライズ往復・Undo/Redo・Prefab 上書き・物理決定性を自動テストで検証する
- **FR-903**: Visual Studio 2022 / Visual Studio 2026 の両方で警告ゼロでビルド・テストが成功し、公開リポジトリの CI で毎回検証する
- **FR-904**: 全コードは constitution の命名規則に従い、自動検査で違反ゼロ
- **FR-905**: 公開 API はリファレンス文書を自動生成し、全公開型・関数に日本語の説明と使用例を持つ
- **FR-906**: 学習教材として、段階的チュートリアル（10 章以上）とサンプルゲーム 5 本（Hello / Breakout / Platformer / Shooter / Puzzle）を同梱する
- **FR-907**: ER 図（er-diagram.md）はデータ構造の正であり、構造変更時に同一変更内で更新されなければならない
- **FR-908**: ファイル形式・公開 API は semver で版管理し、破壊的変更は移行手段を伴う

## Success Criteria *(mandatory)*

- **SC-004**: 振る舞いを変更してから、エディタで再生できるまでが 10 秒以内（増分ビルド時）
- **SC-005**: 授業用標準 PC で、スプライト 10,000 個・動的剛体 1,000 個・パーティクル 20,000 個のシーンで 60 fps を維持する
- **SC-006**: エディタ操作の画面反映は 100 ms 以内、1,000 オブジェクトのシーンを 2 秒以内に開ける
- **SC-007**: シーン/Prefab/全アセット形式の保存→読み込み往復で値が 100% 一致する
- **SC-008**: 同一入力・同一シードで物理シミュレーションが同一結果になる（決定性テスト 100% 成功）
- **SC-009**: エディタ 8 時間連続使用（再生/停止 500 回、モジュール再読み込み 100 回）でクラッシュ 0 件・メモリ増加 10% 以内
- **SC-010**: 自動テスト全件成功、公開 API の全関数に 1 件以上のテスト、コア部の行カバレッジ 80% 以上
- **SC-011**: VS2022 / VS2026 両環境で警告ゼロ・命名規則違反ゼロを CI で毎回確認できる
- **SC-012**: 書き出したゲームがエンジン/エディタ/開発環境の無い PC で起動する

## Assumptions
- 対象 OS は Windows 10/11 x64。Linux ビルドは努力目標（エディタ含む）
- 授業用標準 PC: 4 コア CPU、8 GB RAM、OpenGL 3.3 対応 GPU、1920×1080

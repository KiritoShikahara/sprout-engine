**Created**: 2026-10-21
**Status**: Draft
**Input**: User description: "エディタ付きの学生向けengineを作成したい。sfml＋c++20で。コーディングに関してはプロの設計と命名、クラス分けを要求。命名法則もちゃんと決めてからコーディングをすること。"

## Clarifications

### Session 2026-10-21
- Q: 対象ゲーム → A: 2D 全般（スプライト・タイルマップ・当たり判定）
- Q: エディタ UI → A: ImGui-SFML（シーンツリー・インスペクタ・ビューポート）
- Q: アーキテクチャ → A: Entity + Component（学習しやすさ優先）。利用者が便利で使いやすいこと、利用者に内部構造をできるだけ触らせないこと
- Q: ビルド → A: CMake + vcpkg、Windows/MSVC 主。Visual Studio 2022 と Visual Studio 2026 の両方でビルド可能
- Q: 命名規則 → A: constitution II の規則で確定。テストは GoogleTest で必須

## User Scenarios & Testing *(mandatory)*

### User Story 1 - コードだけで最初のゲームを動かす (Priority: P1)

学生はテンプレートプロジェクトを開き、数十行のコードで「画像を表示し、キー入力で動かす」ゲームを作れる。エンジン内部（描画ループ、リソース管理）を知る必要はない。

**Why this priority**: エンジンの最小価値。エディタが無くてもこれだけで授業に使える。

**Independent Test**: サンプル `HelloSprout` をビルドし、矢印キーでスプライトが動くことを確認できる。

**Acceptance Scenarios**:
1. **Given** テンプレートプロジェクト, **When** シーンにオブジェクトを作り画像を割り当てて実行, **Then** ウィンドウに画像が表示される
2. **Given** 移動処理を書いた振る舞いクラス, **When** 矢印キーを押す, **Then** オブジェクトがフレームレートに依存しない速度で動く
3. **Given** 存在しない画像パス, **When** 実行, **Then** クラッシュせず、ファイル名と対処を示すメッセージが出て代替画像が表示される

---

### User Story 2 - エディタでシーンを組み立てて保存する (Priority: P2)

学生はエディタでオブジェクトを配置・選択・移動し、インスペクタで値を変え、シーンを保存/読み込みできる。保存したシーンはゲームからも読み込める。

**Why this priority**: 「エディタ付き」の中核。コードと見た目の調整を分離できる。

**Independent Test**: エディタでオブジェクトを 3 つ置いて保存→再起動→読み込みで同じ配置に戻る。

**Acceptance Scenarios**:
1. **Given** 空のシーン, **When** オブジェクト追加し画像を割り当てる, **Then** ビューポートとシーンツリーに表示される
2. **Given** 選択中オブジェクト, **When** インスペクタで位置を変える / ビューポートでドラッグ, **Then** 両方の表示が即座に一致する
3. **Given** 編集済みシーン, **When** 保存して読み込み直す, **Then** 全オブジェクトとコンポーネント値が復元される
4. **Given** 操作ミス, **When** 元に戻す（Ctrl+Z）, **Then** 直前の状態に戻る

---

### User Story 3 - エディタ内で再生して確かめる (Priority: P3)

学生はエディタの再生ボタンでゲームを実行し、停止すると編集前の状態に戻る。

**Why this priority**: 試行錯誤のサイクルを短くする。

**Independent Test**: 再生中にオブジェクトが動き、停止後に元の位置へ戻る。

**Acceptance Scenarios**:
1. **Given** 振る舞いを持つシーン, **When** 再生, **Then** 振る舞いが実行される
2. **Given** 再生中, **When** 停止, **Then** シーンは再生前の状態に戻る

---

### User Story 4 - 当たり判定とタイルマップで遊べるゲームにする (Priority: P4)

学生は矩形当たり判定とタイルマップを使い、壁にぶつかる・アイテムを拾うゲームを作れる。

**Why this priority**: 2D ゲーム授業の定番課題を満たす。

**Independent Test**: サンプル `TileCollector` でプレイヤーが壁を通り抜けず、アイテム接触で通知を受け取れる。

**Acceptance Scenarios**:
1. **Given** 当たり判定を持つ 2 オブジェクト, **When** 重なる, **Then** 両者の振る舞いに接触開始/終了が通知される
2. **Given** タイルマップ, **When** エディタでタイルを塗る, **Then** 表示・保存・ゲーム内衝突に反映される

---

### User Story 5 - 音を鳴らす (Priority: P5)

学生は効果音と BGM を名前指定で再生/停止できる。

**Independent Test**: サンプルでキー押下時に効果音、起動時に BGM が鳴る。

**Acceptance Scenarios**:
1. **Given** 音声ファイル, **When** 再生を呼ぶ, **Then** 音が鳴り、同時に複数の効果音が重なっても途切れない

### Edge Cases
- 画像・音声・シーンファイルが無い/壊れている → クラッシュせず、原因を示すメッセージと代替表示
- 破棄済みオブジェクトへの参照を使う → 無効であることを検出でき、操作は無視されログが出る
- 更新処理中にオブジェクトを生成/破棄する → フレーム末に安全に反映
- ウィンドウ最小化・極端に長いフレーム → 時間刻みに上限を設け、物体のすり抜けを抑える
- 新しい版のエンジンで古いシーンファイルを開く → 読み込めるか、版不一致を明示

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 利用者はウィンドウ設定（タイトル・サイズ）を指定してゲームを 1 呼び出しで起動できなければならない
- **FR-002**: 利用者はシーンを作成・切り替えでき、シーン内にオブジェクトを生成・検索（名前）・破棄できなければならない
- **FR-003**: オブジェクトは位置・回転・拡大と親子関係を持ち、親の移動が子に反映されなければならない
- **FR-004**: 利用者はオブジェクトに部品（画像表示、当たり判定、タイルマップ、音、独自の振る舞い）を追加・取得・削除できなければならない
- **FR-005**: 利用者は独自の振る舞いを「開始時」「毎フレーム」「接触時」「破棄時」の処理を書くだけで定義でき、エンジン内部の型に触れる必要がない
- **FR-006**: キーボード・マウスの入力を「押した瞬間 / 押している間 / 離した瞬間」で取得できなければならない
- **FR-007**: 画像・フォント・音声はパス指定で読み込まれ、同一ファイルは一度だけ読み込まれなければならない
- **FR-008**: 矩形の当たり判定で接触開始/継続/終了を通知し、固定物体へのめり込みを解消できなければならない
- **FR-009**: タイルマップ（タイルセット画像 + グリッド）を表示・衝突に使えなければならない
- **FR-010**: テキストを表示できなければならない
- **FR-011**: シーンを人が読めるテキスト形式で保存・読み込みでき、版番号を含まなければならない
- **FR-012**: エディタはシーンツリー、インスペクタ、ビューポート、アセット一覧、ログの各パネルを提供しなければならない
- **FR-013**: エディタでオブジェクトの追加・削除・複製・親子付け替え・選択・ドラッグ移動ができなければならない
- **FR-014**: エディタの編集操作は元に戻す/やり直す（最低 100 手）ができなければならない
- **FR-015**: エディタは再生/一時停止/停止ができ、停止時に再生前のシーンへ戻らなければならない
- **FR-016**: 利用者の独自振る舞いはエディタのインスペクタで追加でき、公開した数値・文字列・真偽値・色のプロパティを編集できなければならない
- **FR-017**: エラーは利用者向けに日本語で「何が・どこで・どうすればよいか」を示さなければならない
- **FR-018**: 利用者が触れる公開部分と内部実装は分離され、利用者が内部実装に依存したコードを書けない構成でなければならない
- **FR-019**: 自動テストが必須であり、公開機能はすべて自動テストで検証されなければならない
- **FR-020**: Visual Studio 2022 と Visual Studio 2026 のどちらでもビルド・テストが成功しなければならない
- **FR-021**: 全コードは constitution で定めた命名規則に従い、自動検査で違反ゼロでなければならない

### Key Entities
- **Game**: 起動設定と実行ループを持つアプリケーション全体
- **Scene**: オブジェクトの集合。保存/読み込みの単位
- **GameObject**: 名前・有効状態・Transform・部品群を持つ。利用者には無効化検出可能な参照として渡る
- **Component**: オブジェクトに付く部品（Transform, SpriteRenderer, TextRenderer, BoxCollider, TileMap, AudioSource）
- **Behavior**: 利用者が書く振る舞い部品。公開プロパティを持てる
- **Asset**: 画像・フォント・音声・シーンファイル。パスで識別
- **EditorCommand**: 元に戻せる編集操作の単位

## Success Criteria *(mandatory)*

### Measurable Outcomes
- **SC-001**: 初学者がテンプレートから「画像をキーで動かす」までを 30 分以内、30 行以内のコードで達成できる
- **SC-002**: 利用者向けサンプルコードにエンジン内部の型・名前空間が 1 つも現れない
- **SC-003**: オブジェクト 1,000 個・スプライト表示ありで 60 fps を維持する（授業用標準 PC）
- **SC-004**: シーン保存→読み込みで全値が一致する（往復テスト 100% 成功）
- **SC-005**: エディタ操作に対する画面反映が体感遅延なし（100 ms 以内）
- **SC-006**: 自動テストが全て成功し、公開 API のテスト網羅率 100%（全公開メソッドに 1 件以上）
- **SC-007**: VS2022 / VS2026 の両環境で警告ゼロビルド、命名規則違反ゼロ

## Assumptions
- 対象は Windows 10/11。Linux ビルドは努力目標
- 物理は矩形（AABB）中心の簡易版。回転した形状や剛体シミュレーションは対象外
- 独自振る舞いは C++ で書き、エディタ再生はエンジンとゲームコードを同時ビルドしたエディタ実行ファイルで行う（ホットリロードは対象外）
- ネットワーク、3D、スクリプト言語組み込み、モバイルは対象外
